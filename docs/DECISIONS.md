# 결정 기록

누가 언제 무엇을 정했는지 적는다. 상태는 셋이다.

- **확정** — 사용자가 말로 정했다. 인용은 사용자의 말 그대로다.
- **전제** — 사용자가 명시적으로 승인하지는 않았지만 지금의 계획과 문서가 깔고 있다. 전제를 뒤집는 작업은 먼저 사용자에게 묻는다.
- **미정** — 아직 정해지지 않았다. "정하는 곳"에 적힌 단계의 단계 계획 문서에서 안을 만들고, 사용자가 확인하면 정해진다. "그때까지 시작하지 않는 것"에 적힌 일은 그 전에 시작하지 않는다.

결정이 생기거나 바뀌면 이 문서에 한 줄을 더하고, 그 결정이 바꾸는 다른 문서를 같은 커밋에서 고친다.

## 버린 안

### Astryx 디자인 시스템 (2026-11-25에 버림)

Astryx(`@astryxdesign/core` 0.7.17)는 React 19 전용이다(peer `react >=19.0.0`, React 컴포넌트가 `useOptimistic`·`use`·`<Activity>`·prop으로 받는 `ref`를 쓴다). dsh 웹 클라이언트는 React 18.3.1을 플러그인과 공유한다. 그래서 Astryx는 dsh 슬롯이 그린 요소 안에 React 19 루트를 따로 띄우는 방식으로만 쓸 수 있다.

2026-11-24에 이 방식이 동작함은 확인했다(공식 예제 156개, 요소 4,629개를 빈 페이지와 dsh 안에서 속성 단위로 비교). 버린 이유는 계속 치러야 하는 값이다.

- 브라우저 번들에 React 19와 Astryx를 실어야 한다(시험에서 약 1MB).
- React 19 트리 안에서는 dsh의 슬롯 props와 훅을 쓸 수 없어, 값을 넘기는 다리를 따로 만들어야 한다.
- 스타일이 양방향으로 간섭한다(Astryx 테마의 맨 요소 규칙이 dsh 화면에 번짐, 리셋 범위 밖에 그려지는 토스트, dsh 전역 규칙이 Astryx 모서리·포커스 링을 바꿈). 처방은 찾았지만 Astryx 버전을 올릴 때마다 다시 확인해야 한다.
- 여러 자리에 그리려면 React 19 루트 하나에서 포털로 그려야 한다(독립 루트 여럿은 서로의 테마 속성을 지운다).
- DreamVerse 모양은 디자인 시스템이 아니라 직접 쓴 React 컴포넌트와 CSS에서 나온다. 채팅은 어느 쪽이든 dsh 것이라 Astryx를 쓰면 두 모양이 한 화면에 섞인다.

### 덧붙이기형 화면 (2026-11-24에 버림)

기본 dsh 화면을 그대로 두고 사이드바에 패널 하나를 더하는 방식이다. 2026-11-24에 만든 검토용 골격이 이 방식이었다. 사용자가 DreamVerse처럼 화면을 교체하기로 했다.

### dsh 포크 (전제로 버린 상태)

DreamVerse는 dsh를 포크했다(분기 뒤 업스트림 병합 없음, 그 사이 업스트림은 9,000커밋 넘게 진행). 포크하면 코어에 확장점을 직접 넣을 수 있지만 업스트림을 따라가는 일을 떠안는다. 필요한 화면 구성이 포크 없이 됨을 확인했으므로 포크하지 않는다. 명시 승인은 아니어서 위 "전제"에 두었다.

### 검토용 골격 (2026-11-25에 지움)

2026-11-24에 만든 `packages/bundle`·`packages/ui-shell`·`scripts/`는 Astryx 아일랜드 + 덧붙이기형이었다. 사용자 요청으로 지웠다. 거기서 확인한 구성(프로필 만들기, 번들 선언, 브라우저 번들 형식)은 `docs/DSH.md`에 옮겨 적었다.
