# 단계 계획 — 1-5 접속·배포

`docs/ROADMAP.md` 1-5의 상세 계획이다. 브랜치는 `1-5-access-deploy`다(2026-11-28).

## 범위

`docs/DECISIONS.md` "미정"의 "접속과 로그인 방식"을 정한다: dsh 웹을 리버스 프록시 뒤에 띄우는 구성, 토큰 주소 로그인의 실제 흐름, 프록시 쪽 인증을 더할지. 정하기 전에 프록시 뒤의 동작을 띄워서 시험했다(아래 "확인한 사실"). 이 저장소는 공개이므로 사용자의 실제 서버·네트워크는 적지 않는다. 예시의 호스트 이름은 `studio.example.com`이다.

## 확인한 사실

2026-11-28에 이 단계의 워크트리에서 실험으로 봤다. **띄워 확인**은 실험용 조합 시험이다: dsh 0.2.2-rc.5를 루프백에 띄우고 그 앞에 의존성 없는 Node 리버스 프록시(일부는 컨테이너의 nginx 1.27과 Caddy 2.8)를 두고, 헤드리스 Chromium이 다른 호스트 이름으로 프록시에 접속했다. **소스 확인**은 업스트림 `packages/client/connection/src/`(`browser-auth.ts`, `api-request-trust.ts`, `rpc-host.ts`), `packages/bundle/web-app/src/`, `docs/user/guide/public-deployments.md`다.

**프록시 뒤에서 필요한 것**

- dsh 쪽에 필요한 옵션은 **`--trusted-host <브라우저가 보는 호스트>` 하나**다. `--public-url`은 출력되는 로그인 주소와 표시용이고 신뢰를 주지 않는다. `--host`는 건드리지 않는다(기본은 루프백. **띄워 확인**: 둘 다 준 것, `--trusted-host`만 준 것, `--public-url`만 준 것을 각각 돌렸다).
- `--trusted-host`가 없으면 페이지(`/`)는 열리지만 `/api/*`와 `/cs/events`가 전부 403이다. 화면은 "Reconnecting…"에서 멈춘다(**띄워 확인**). 원인은 dsh의 Host·Origin 검사다: Host가 루프백, 듣는 주소, 신뢰 목록 가운데 하나여야 하고 `Origin`이 있으면 Host와 같아야 한다(**소스 확인**).
- **프록시는 브라우저의 Host를 그대로 넘겨야 한다.** 업스트림 주소로 바꾸면 Origin과 어긋나 403이 된다(**띄워 확인**).
- **WebSocket 업그레이드를 전달해야 한다.** dsh의 실시간 채널이 `/api/remote.mux`의 WebSocket이다. 업그레이드 헤더를 넘기지 않는 nginx 설정에서는 연결이 404로 실패했다(**띄워 확인**). 우리 이벤트 스트림 `/cs/events`는 SSE다.
- dsh는 `X-Forwarded-*`를 읽지 않는다. 쿠키의 `Secure`는 dsh가 직접 TLS로 들을 때만 붙는다(**띄워 확인**, **소스 확인**).
- 프록시가 HTTPS이고 dsh가 평문이어도 로그인, 프로젝트 만들기, 채팅, 이벤트 스트림이 모두 되고 콘솔 오류가 0건이다(**띄워 확인**). HTTPS 없이 HTTP 프록시와 루프백이 아닌 호스트 이름으로도 된다(**띄워 확인**. 이때 토큰이 평문으로 오간다).
- **이벤트 스트림은 버퍼링 없이 흐른다.** Node 프록시, nginx 기본 설정, Caddy 기본 설정에서 연산을 실행하고 20~30ms 안에 이벤트가 왔다(**띄워 확인**). 우리 헤더 `x-accel-buffering: no`를 nginx가 무시하게 한 대조군에서도 흘러서, 그 헤더가 꼭 있어야 하는지는 가르지 못했다(**미확인**).
- 프록시 쪽 Basic 인증은 dsh와 부딪치지 않는다. dsh는 `Authorization` 헤더를 읽지 않는다(**띄워 확인**: Basic 인증을 건 HTTPS 프록시 뒤에서 채팅과 WebSocket까지. **소스 확인**).
- 경로 접두사(`https://example.com/studio/`)에 올리는 것은 dsh는 지원한다고 하지만 우리 셸이 `/api/cs/…`와 `/cs/events`를 절대 경로로 부른다(**소스 확인**. 띄워 보지 않았다). 호스트 이름의 뿌리에 올린다.
- 프록시 없이 dsh가 직접 TLS로 듣게 할 수도 있다(`--tls-cert`, `--tls-key`. **띄워 확인**). 인증서를 바꾸면 다시 띄워야 한다.
- `--host <LAN 주소>`로 프록시 없이 직접 열 수도 있다. dsh가 평문이라는 경고를 찍는다. 모든 주소(`0.0.0.0`)로 듣는 것은 dsh가 거절한다(**띄워 확인**).

**로그인**

- 토큰은 프로세스마다 새로 만든다. 같은 home으로 다시 띄우면 토큰이 바뀌고 앞의 토큰은 401이다. 설정이나 환경 변수로 고정하는 길, 다시 찍는 길은 없다(**띄워 확인**: 토큰의 해시를 비교했다. **소스 확인**).
- 토큰이 든 주소를 열면 쿠키를 받고 토큰 없는 주소로 넘어간다. 쿠키는 `HttpOnly; SameSite=Strict; Path=/`이고 수명은 30일이다(연장되지 않는다. `connection` 행의 `cookieMaxAgeDays`로 바꾼다. **띄워 확인**).
- 쿠키는 호스트(HTTP에서는 포트까지)에 묶인다. 주소가 다르면 따로 로그인한다(**띄워 확인**).
- **같은 home이면 다시 띄워도 쿠키가 유효하다.** 서명 비밀이 `$DSH_HOME/.credentials.yaml`에 있다(**띄워 확인**). 새 토큰이 필요한 것은 쿠키가 없는 브라우저와 쿠키가 만료된 브라우저뿐이다.
- 비밀번호나 계정 로그인은 없다. 토큰 로그인은 소유자(`owner`)다(**소스 확인**).
- 로그인하지 않은 요청: `/`는 401과 안내 글, `/api/cs/projects`와 `/cs/events`는 401이다. 정적 파일은 인증 없이 나간다(**띄워 확인**).
- **로그인 주소는 표준 출력에 찍힌다.** 서비스로 돌리면 그 줄이 로그에 남는다. 토큰은 프로세스가 사는 동안 유효하다.

**새 브라우저의 빈 채팅**

- 저장된 상태가 없는 브라우저가 앞 세션이 아니라 새 빈 채팅을 여는 것은 dsh의 동작이다. dsh는 보던 세션을 브라우저의 localStorage(`dsh.sessions.current`, 출처별)에 두고, 값이 없으면 가장 최근 작업공간의 빈 세션을 열거나 만든다(**띄워 확인**: 그 값을 옮긴 브라우저는 앞의 대화를 열었다. **소스 확인**: 업스트림 `packages/client/ui-workspace/src/client/navigation.ts`의 `restoreSelection`).
- 같은 브라우저라도 접속 주소가 다르면 저장이 따로다. 접속 주소를 하나로 정해 쓰면 기기마다 처음 한 번만 겪는다.

## 사용자가 정할 것

### 1. 접속 형태

| 안 | 구성 | 좋은 점 | 나쁜 점 |
| --- | --- | --- | --- |
| A. 리버스 프록시 + TLS, 프록시 쪽 인증 추가 | 프록시가 TLS를 끝내고 자체 인증(Basic 인증 등)을 건 뒤 dsh로 넘긴다 | 방어선이 둘이다. 토큰이 새도 프록시 인증이 남는다 | 프록시의 자격 증명을 따로 관리한다. 기기마다 프록시 인증 한 번 + 토큰 주소 한 번 |
| B. 리버스 프록시 + TLS, 토큰 로그인만 | 프록시는 TLS와 전달만 한다 | 구성이 가장 단순하다 | 방어선이 토큰 하나다. 로그에 남는 로그인 주소를 반드시 막아야 한다 |
| C. 사설망(LAN·VPN) 전용, 프록시 없음 | `--host <사설 주소>`나 dsh의 직접 TLS | 프록시가 없다 | 평문이면 토큰이 그대로 오간다. 사설망이 방어선이다 |

어느 안이든 이 저장소가 담는 것은 같다: 확인된 dsh 옵션과 프록시 요건, 일반화한 nginx·Caddy 예시, 로그인 주소가 로그에 남지 않게 하는 주의, 그리고 프록시 뒤의 흐름을 보는 조합 시험. 실제 서버의 구성은 이 저장소에 적지 않는다.

### 2. 새 브라우저에서 무엇을 열지

| 안 | 내용 | 드는 것 |
| --- | --- | --- |
| 가. 가장 최근 대화를 연다 | 저장된 상태가 없는 브라우저로 열었고 그 프로젝트에 대화가 있으면, 셸이 가장 최근 세션으로 옮긴다 | 셸의 구독 하나(`follow.ts`). dsh의 공개 서비스만 쓴다. dsh의 복원이 끝난 때를 잡아야 해서 조합 시험으로 굳힌다 |
| 나. 홈을 연다 | 저장된 상태가 없는 브라우저는 프로젝트 카드가 있는 홈에서 시작한다 | 셸의 구독 하나. 가보다 단순하다 |
| 다. 그대로 둔다 | 마지막 프로젝트의 새 빈 채팅이 열린다(지금 동작). 앞의 대화는 내비게이터에서 고른다 | 없음 |

### 실험에서 돌린 것(시험으로 남기지 않았다)

- 컨테이너의 nginx 1.27과 Caddy 2.8을 dsh 앞에 두고 이벤트 스트림이 바로 오는지 봤다. nginx는 업그레이드 헤더를 넘기는 설정과 넘기지 않는 설정, `X-Accel-Buffering`을 무시하는 설정을 돌렸다.
- 자체 서명 인증서를 쓰는 HTTPS Node 프록시(쿠키에 `Secure`를 덧붙이는 것과 아닌 것), 그 위의 Basic 인증.
- dsh의 직접 TLS(`--tls-cert`, `--tls-key`)와 `cookieMaxAgeDays`, `--host <사설 주소>`.
- 새 브라우저에 dsh의 저장 값(`dsh.sessions.current`)을 옮겨 주면 앞의 대화가 열리는 것.

### 계획과 달라진 것

- 완료 기준의 "다른 기기의 브라우저"는 같은 장비에서 프록시를 거쳐 다른 호스트 이름으로 접속하는 조합 시험으로 대신했다. 실제 다른 기기와 실제 인증서로 하는 확인은 배포하는 쪽에 남는다.
- 구현 뒤에 지휘 세션이 하나를 고쳤다: 시작 복원이 연 세션의 기록(`restoredSession`)이 페이지가 열려 있는 동안 남아, 사용자가 나중에 일부러 연 빈 채팅까지 건너뛰었다. 첫 이동이 가져가고 지우게 했다.
