# 단계 계획 — 1-4 기능 대응 확정

`docs/ROADMAP.md` 1-4의 상세 계획이다. 브랜치는 `1-4-feature-mapping`이다(2026-11-28).

## 범위

1. dsh에 맡기려는 기능을 실제로 써 본다(예약, MCP, 스킬, 웹 도구, 서브에이전트, 첨부, 메시지 재생성·편집).
2. `docs/LEGACY.md` 대응표의 "후보"와 "미정"을 사용자와 정하고, 옮길 기능의 순서를 정한다.
3. 에이전트 프리셋에 무엇을 넣을지 정하고(`docs/DECISIONS.md` "미정"), 정한 구성의 프리셋을 번들에 넣는다. 우리 프리셋으로 만든 세션의 에이전트가 정한 도구만 가지는지 조합 시험으로 본다.

## 확인한 사실

2026-11-28에 이 단계의 워크트리에서 실험으로 봤다. **띄워 확인**은 dsh 0.2.2-rc.5를 가짜 LLM 서버와 함께 띄운 실험용 조합 시험이고(대본이 dsh의 도구를 부른다), "실제 모델"이라고 적은 것은 사용자의 OpenAI 호환 서버의 모델로 한 번씩 본 것이다. **소스 확인**은 업스트림 태그 `dsh-v0.2.2-rc.5`의 소스와 문서다. 실험은 기본 프리셋 `standard`에서 했고, 프리셋 실험만 우리 구성으로 했다.

### dsh의 기능

| 기능 | 되는 것 | 없는 것(기존 앱과 견주어) |
| --- | --- | --- |
| 예약 | 에이전트가 `schedule_create`(`title`, `prompt`, `rrule`, `target`)로 만들면 정한 때에 그 세션(또는 새 세션)에 메시지가 와서 턴이 돈다. dsh를 껐다 같은 home으로 켜도 예약이 남고, 꺼진 동안 지난 것은 켠 직후에 한 번 돈다. 새 세션으로 도는 예약의 세션은 그 프로젝트에 붙어 우리 내비게이터에 뜬다. "Automation tasks" 화면이 우리 셸에서도 열리고, 에이전트 없이 화면에서 만들 수 있다(**띄워 확인**). 실제 모델이 말로 한 요청에서 맞는 예약을 만들었다 | 실행의 성공·실패 기록(dsh는 "보냈다"까지만 남긴다), 연속 실패 뒤 자동 끄기, 예약마다의 역할·도구 허용, 실행별 안 읽음. 최소 간격은 60초다. 정확히 한 번을 보장하지 않는다(**소스 확인**) |
| MCP | `mcp-manager` 행의 `config.servers`에 stdio 서버를 적으면 도구가 `mcp__<서버>__<도구>`로 에이전트에게 가고 실행된다. 서버의 안내문이 시스템 프롬프트에 든다(**띄워 확인**). 비밀값은 `${credential:이름}`으로 참조만 적는다. 플러그인이 `ctx.mcpManager.register`로 서버를 등록할 수도 있다(**소스 확인**) | 서버를 더하는 설정 화면(브라우저 쪽 패키지에서 찾지 못했다). 더하려면 프로필의 패치 파일을 고친다 |
| 스킬 | `skill-filesystem` 행이 가리킨 폴더의 `<이름>/SKILL.md`가 스킬 목록으로 에이전트에게 가고 `skill` 도구가 본문을 읽는다. 플러그인이 `ctx.skills.register`로 파일 없이 스킬을 등록해도 같다(**띄워 확인**). 실제 모델이 설명만 보고 맞는 스킬을 골랐다 | 스킬 폴더를 가져오는 화면, 스킬의 버전 기록, 자동 개선 |
| 웹 도구 | `web_fetch`가 페이지를 가져와 Markdown으로 바꾼다(**띄워 확인**) | 검색. 검색 백엔드가 없으면 `web_search`는 도구 목록에 없다. dsh가 주는 백엔드(`web-search-deepseek`)는 DeepSeek 계정이나 키가 있어야 한다(**소스 확인**. 키가 없어 써 보지 못했다, **미확인**) |
| 웹 검색을 꽂는 자리 | 플러그인이 `ctx.web.registerSearchProvider({ id, available, search })`로 검색 백엔드를 등록하고 `web` 행의 `searchProvider`로 고르면 `web_search`가 생긴다(**띄워 확인**: 시험용 가짜 백엔드) | — |
| 서브에이전트 | `subagent`(`description`, `prompt`)를 부르면 자식 에이전트가 따로 돌고, 끝나면 마지막 글이 부모에게 메시지로 와서 부모가 이어 간다. 자식은 부모의 구성을 물려받아 우리 프로젝트 도구와 프로젝트 규칙·상태를 받는다. 자식 세션은 우리 내비게이터에 줄로 뜨지 않는다(**띄워 확인**). `tool-subagent` 행의 `agentPreset`·`allowedAgentPresets`로 자식의 프리셋을 정하거나 고르게 할 수 있다(**소스 확인**) | 이름 있는 역할 에이전트, 검수 판정(통과·반려)과 재시도, 위임 카드 |
| 첨부 | 입력창이 파일을 받는다. 이미지는 모델이 이미지 입력을 받는다고 선언돼 있으면 요청에 이미지로 실린다(PNG·JPEG·WebP·GIF, 20장까지). 다른 파일(오디오, 영상, 글)은 home의 첨부 저장소에 사본이 생기고 에이전트에게는 그 경로를 알리는 글만 간다(**띄워 확인**). 호스트 플러그인은 `ctx.attachments`로 참조에서 경로와 바이트를 얻는다(**소스 확인**) | 오디오·영상을 에이전트가 볼 수 있는 모양(프레임, 스펙트로그램, 받아쓰기)으로 바꾸는 것. 첨부가 프로젝트의 에셋이 되는 것(저장소는 프로젝트 폴더가 아니라 home이다) |
| 메시지 | 복사, 좋아요·싫어요, "Branch into a new conversation"(그 메시지에서 새 세션으로 갈라진다. 우리 내비게이터에 뜬다. **띄워 확인**) | 답 다시 만들기, 보낸 글을 고쳐 다시 보내기(버튼도 메뉴도 문자열도 없다) |
| 대화 검색·기억 | 세션 전문 검색 백엔드(`session-query-sqlite`)가 있고 입력창의 `@`로 다른 세션을 참조할 수 있다(**소스 확인**) | 에이전트가 쓰는 대화 검색 도구, 우리 셸의 검색 입력(dsh 사이드바를 교체하며 빠졌다). 기억은 서드파티 MCP 서버의 예시 구성뿐이다 |
| 진행·안 읽음 | 브라우저 쪽에 세션별 `running`·`pendingInteraction`·`completionUnread`를 주는 서비스가 있다(**소스 확인**) | 우리 내비게이터의 표시(그리지 않았다) |

### 에이전트 프리셋

- **우리 프리셋을 넣고 기본으로 둘 수 있다.** `@deepseek-ai/dsh-agent-preset` 행을 넣고 `agent-preset-registry` 행의 `config.default`를 그 id로 두면 새 세션이 그 프리셋으로 만들어진다(**띄워 확인**. 프로필 계층과 `--patch`로 넣어 봤다).
- **우리 도구는 프리셋과 상관없이 간다.** 프로젝트 도구 여덟 개와 연산 도구, 시스템 프롬프트의 프로젝트 규칙 절, 프로젝트 상태 메시지가 어느 구성에서나 왔다(**띄워 확인**).
- **구성별로 모델이 받는 dsh 도구와 첫 요청의 크기**(**띄워 확인**. 토큰은 `standard`를 약 11,000으로 본 비율의 어림이다):

  | 구성 | 넣은 것 | dsh 도구 | 첫 요청 |
  | --- | --- | --- | --- |
  | `standard`(지금) | 셸, 파일, 검색, 예약, 스킬, 웹, 서브에이전트 등 | 31개(`bash`, `write`, `edit` 포함) | 약 11,000토큰 |
  | 최소 | 페르소나, 스킬, 사용자에게 묻기, 압축 | 3개: `ask_user_question`, `skill`, `working_directory` | 약 3,300 |
  | 최소(정리) | 위에서 dsh 개발용 안내·오피스 스킬·`working_directory`를 끔 | 2개 | 약 2,600 |
  | 기능 포함 | 최소 + 웹 가져오기, 예약, 할 일, 서브에이전트 묶음 | 16개(`web_fetch`, `schedule_*`, `todo_write`, `subagent`, `subagent_fork`, `workflow`, `list_agents`, `send_message`, `wait_agent` 등) | 약 7,300 |
  | 기능 + 읽기 | 위 + 읽기 전용 파일 도구 | 20개(`read`, `read_image`, `glob`, `grep` 추가. `write`·`edit`·`bash` 없음) | 약 8,000 |

- **페르소나**는 `persona` 플러그인의 `prefix`로 정한다. 바꾸면 "You are a coding agent…" 자리에 우리 문장이 든다(**띄워 확인**). `complete: true`는 프로젝트 규칙 절까지 지우므로 쓰지 않는다(**소스 확인**).
- **프리셋 밖에서 붙는 것**: `working_directory` 도구(`tool-working-directory` 행), dsh 개발용 안내 문단(`harness-dev-context` 행), 오피스 스킬 넷(`skill-office` 행), "You are an AI agent powered by DeepSeek Harness." 첫 줄(`system-prompt` 행의 `includeHarnessIdentity`). 행을 끄거나 설정으로 뺄 수 있다(**띄워 확인**).
- **세션마다 프리셋을 줄 수 있다.** 기본이 무엇이든 만들 때 준 프리셋의 도구를 받는다(**띄워 확인**: 호스트에서 만들었다). 우리 셸은 `packages/ui-shell/src/client/host.ts`의 `openWorkspace` 한 곳에서 세션을 만든다.
- **사용자가 고른 기본 프리셋이 번들의 기본값을 이긴다**(설정 → Agent presets의 "make default". **띄워 확인**). 우리 셸에서 프리셋을 고르는 곳은 그 설정 화면뿐이다.
- **기본 제공 프리셋 넷의 행을 끄면**(`preset-standard`, `-ptc`, `-minimal`, `-cordis`에 `disabled: true`) dsh는 뜨고 목록에 우리 것만 남는다. 그 프리셋으로 만든 **기존 세션은 이어 쓸 수 없게 된다**: 앞의 대화는 보이지만 새 글이 보내지지 않고 화면에 오류도 없다(**띄워 확인**).
- **파일 정책**: 기본은 작업 폴더 안 쓰기 허용(`workspace-write`)이고 사용자가 입력창의 칩으로 세션마다 바꾼다. 하위 폴더를 빼는 설정은 없다. `tool-fs`는 `write: false`, `edit: false`로 읽기 전용이 되지만 `bash`에는 그런 설정이 없다(**소스 확인**).
- **서브에이전트의 자식**은 따로 정하지 않으면 부모의 프리셋을 따른다(**소스 확인**).

## 사용자가 정할 것

### 1. 에이전트 프리셋에 넣을 것

| 안 | 에이전트가 가지는 것 | 좋은 점 | 나쁜 점 |
| --- | --- | --- | --- |
| A. 기능 포함, 셸·파일 없음(권함) | 우리 도구 + 스킬, 사용자에게 묻기, 웹 가져오기, 예약, 할 일, 서브에이전트 | "프로젝트를 바꾸는 길은 연산 하나"가 도구 수준에서 지켜진다. dsh에 맡기기로 한 예약·위임·웹을 에이전트가 쓴다 | 첫 요청이 최소 구성의 약 2배다 |
| B. 최소 | 우리 도구 + 스킬, 사용자에게 묻기 | 가장 작고 단순하다 | 에이전트가 예약을 만들지 못하고(화면에서는 된다) 웹과 위임이 없다 |
| C. A + 읽기 전용 파일 도구 | A + `read`, `glob`, `grep`, `read_image` | 에이전트가 프로젝트 폴더의 파일을 직접 읽는다 | 기록 파일도 읽힌다. 상태는 이미 프로젝트 도구로 읽는다 |
| D. `standard` 그대로 | 셸과 파일 쓰기까지 | 프로젝트 문서를 파일로 다룬다 | 에이전트가 기록 밖에서 프로젝트 폴더를 고치고 지울 수 있다. 도메인 규칙("직접 지우지 않는다")이 서지 않는다 |

A에서 `workflow`(자식 에이전트 여럿을 스크립트로 엮는 도구)와 `subagent_fork`는 뺀다. 프로젝트 문서는 A·B·C에서는 파일이 아니라 기능 컴포넌트의 연산으로 만든다(버전이 기록으로 남는다).

### 2. 기본 제공 프리셋

| 안 | 내용 | 좋은 점 | 나쁜 점 |
| --- | --- | --- | --- |
| 가. 그대로 두고, 셸이 늘 우리 프리셋으로 세션을 만든다(권함) | 번들의 기본값을 우리 프리셋으로 두고, 우리 화면이 만드는 세션에는 프리셋을 명시한다 | 설정에서 기본값을 바꿔도 우리 화면의 세션은 우리 프리셋이다. 기존 세션이 그대로 돈다 | 설정 화면에 `standard` 등이 계속 보인다. dsh가 스스로 만드는 세션(예약의 새 세션)은 설정의 기본값을 따른다 |
| 나. 기본 제공 프리셋을 끈다 | 가에 더해 네 행을 끈다 | 목록에 우리 것만 남는다 | 그 프리셋으로 만든 기존 세션에 글이 보내지지 않는다(오류 표시도 없다) |

### 3. 대응표의 "후보"와 옮길 순서

권하는 판정이다. 1번에서 A·B·C를 골랐을 때의 것이다.

| 기존 기능 | 판정 | 내용 |
| --- | --- | --- |
| 메시지 재생성·편집 | 뺀다 | dsh에 없다. dsh의 분기("Branch into a new conversation")로 대신한다 |
| 진행·안 읽음 | dsh + 표시는 우리가 | 데이터는 dsh에 있다. 내비게이터에 그리는 일을 화면 단계의 후속으로 둔다 |
| MCP 서버 | dsh | 서버 추가는 프로필 패치로 한다. 설정 화면의 카드는 필요해지면 3-5에서 본다 |
| 예약 실행 | dsh | Automation tasks 화면과 예약 도구. 실행 결과 기록과 자동 끄기는 옮기지 않는다 |
| 페이지 가져오기 | dsh | `web_fetch` |
| 웹 검색 | 우리가 만든다(작다) | dsh의 검색 자리에 검색 백엔드 어댑터를 꽂는 플러그인. 기존 `lib/search`가 출발점이다 |
| 프리셋, 자동 개선 | 우리가 만든다 | 기능 컴포넌트(저장, 버전, 제안 후 승인, 모델 파일 패턴으로 자동 적용). 에이전트에게 싣는 길만 dsh 스킬 서비스를 쓴다 |
| 스킬 가져오기 | dsh 스킬 폴더 | 가져오는 화면은 만들지 않는다. 스킬 폴더에 넣으면 실린다 |
| 역할 에이전트, 위임 | dsh 서브에이전트 | 역할은 에이전트 프리셋으로, 검수와 재시도의 순서는 작업 절차(2-4)의 스킬로 적는다 |
| 기억 | 프리셋 기능에 맡긴다 | 기존에도 프리셋 위에 있었다. 따로 만들지 않는다 |
| 대화 검색 | dsh + 입력은 우리가 | dsh의 세션 검색에 내비게이터의 검색 입력을 잇는 일을 화면 단계의 후속으로 둔다 |
| 첨부 | dsh | 이미지는 그대로. 첨부가 에셋이 되는 것은 2-5(채팅 참조)에서, 오디오·영상을 에이전트에게 보이는 변환은 미디어 검수를 옮길 때 만든다 |
| 프로젝트 문서와 버전 | 우리가 만든다 | 기능 컴포넌트의 연산으로 쓰고 버전은 기록으로 남긴다 |

옮길 순서(2-3): 에셋 → 워크플로 → 생성·배치·검토 → 캐릭터 → 프리셋 → 프로젝트 문서 → 웹 검색 → 아래 4번에서 옮기기로 한 것.

### 4. 대응표의 "미정"

옮길지부터 정해지지 않은 것이다: 미디어 검수(ffmpeg, 받아쓰기), Blender 렌더, S3 호환 스토리지와 백업·내보내기, 사용량·요금 집계. 옮기기로 한 것만 로드맵에 단계로 더한다.

### 실험에서 돌린 것(시험으로 남기지 않았다)

- 구성 다섯(`standard`, 최소, 최소(정리), 기능 포함, 기능 + 읽기)을 가짜 LLM으로 띄워 도구 목록과 요청 크기를 쟀다.
- 기본 제공 프리셋 넷을 끄고 설정 화면과 기존 `standard` 세션을 봤다. 사용자의 기본값(`selectedDefault`)이 번들의 기본값을 이기는 것, 레지스트리 행을 `--patch`로 덮으면 설정 쓰기가 거절되는 것.
- `standard`에서 예약(일회성 예약이 세션으로 들어오는 것, 재시작 뒤에도 남는 것, Automation tasks 화면, 화면에서 만들기), MCP stdio 서버, 스킬(폴더와 플러그인 등록), `web_fetch`, 가짜 검색 백엔드로 `web_search`가 생기는 것, 서브에이전트, 이미지와 그 밖의 파일 첨부, 메시지의 버튼과 분기.
- 실제 모델로 예약 만들기, 스킬 고르기, 서브에이전트 위임을 한 번씩.

### 계획과 달라진 것

- 계획의 A에 있던 예약 도구는 리뷰 뒤에 뺐다.
- 계획의 2번 "가"는 dsh가 스스로 만드는 세션의 예로 예약의 새 세션만 들었다. 리뷰가 우리 화면 안의 다른 진입점을 찾았고 셸이 빈 채팅을 되돌리게 했다.
- "기능 + 읽기"와 "최소(정리)" 구성의 `includeRuntimeContext: false`는 쓰지 않았다.
