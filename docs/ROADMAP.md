**채팅에서 워크플로 하나를 local ComfyUI로 실행하고, 결과 이미지가 가운데 갤러리에 뜬다.**

네 계획이 따로 가다가 마지막에야 만나는 것을 막으려고 가장 먼저 잡는 목표다. 필요한 단계는 1-0, 1-1, 1-2, 1-3, 2-0, 2-1, 2-2, 2-3의 에셋·생성 최소분, 3-0, 3-2의 최소분, 4-0, 4-1, 4-2다. 각 단계에서 이 목표에 필요한 만큼만 먼저 만든다.

## 단계를 다루는 법

- 단계 하나가 브랜치 하나·PR 하나다(`AGENTS.md` "브랜치·커밋·병합"). 2-3만은 갈래(`2-3a`, `2-3b` …) 하나가 브랜치 하나·PR 하나다(사용자가 정함, 2026-11-28). 단계 계획 문서도 갈래마다 쓴다(`docs/PLAN_2-3d.md`).
- 단계를 시작할 때 **단계 계획 문서** `docs/PLAN_<단계>.md`(예: `docs/PLAN_2-1.md`)에 상세 계획과 설계 결정을 쓴다. 끝나면 `docs/archive/`로 옮기고 경로를 고친다.
- 끝낸 단계는 아래에서 `[x]`로 바꾸고 무엇을 어느 패키지에서 했는지 한 줄로 적는다. 남긴 일은 `[ ]`나 "후속"으로 적는다.
- 아래 단계 목록은 출발점이다. 단계를 시작할 때 범위를 사용자와 다시 맞춘다.
- 단계가 정해야 하는 "미정"(`docs/DECISIONS.md`)은 단계 계획 문서에 안을 쓰고 사용자가 확인한 뒤에 구현한다.

## 계획 3 — 화면

DreamVerse처럼 기본 dsh 화면을 교체한다. Astryx 없이 React 18 컴포넌트, dsh 기본 부품, 직접 쓴 CSS로 그린다. 읽을 문서는 `docs/DSH.md` "화면 교체"·"그릴 재료"와 업스트림 `docs/subsystems/slots.md`다. 넷 중 가장 크다(DreamVerse 화면 코드 약 21,000줄, 기존 앱 화면의 `.tsx` 약 21,600줄).

- [x] **3-0 셸** — `packages/ui-shell`(`@cs/ui-shell`)의 브라우저 절반이 기본 dsh 화면을 교체한다: 브랜드(이름 ComfyStudio와 임시 마크), "새 프로젝트" 버튼(dsh의 새 세션 버튼 자리), 왼쪽 내비게이터(홈, 프로젝트와 그 채팅 세션, 이름 바꾸기, 목록에서 빼기, 새 채팅), 가운데의 홈(프로젝트 카드)과 프로젝트 틀(위쪽 줄 + 다른 패키지의 화면이 꽂히는 자식 슬롯 `cs.center.view`), 우측 패널의 채팅 탭, 실패 알림. 1-1의 시험용 React 컴포넌트는 지웠다(2026-11-28). 상세는 `docs/archive/PLAN_3-0.md`.

  - 정한 것(Claude가 고른 기본값. `docs/DECISIONS.md` "전제"): 홈에는 채팅이 없다, 열린 프로젝트는 dsh의 주 세션을 따른다(URL에 위치를 적지 않는다), 새 프로젝트는 "새 프로젝트"라는 제목으로 바로 만든다, 화면용 API 클라이언트는 셸 안에 둔다.
  - 확인한 것: 조합 시험(`tests/integration/shell.test.ts`)이 실제 dsh와 브라우저에서 브랜드 → 빈 홈 → 프로젝트 만들기 → 우측 채팅 탭의 입력창에 글 쓰기 → 이름 바꾸기 → dsh 페이지(Plugins)에서 돌아오기 → 홈 카드로 다시 열기 → 둘째 프로젝트를 목록에서 빼기(폴더는 남는다) → 브랜드를 눌러도 홈에 남기 → 홈과 다른 프로젝트를 다녀와도 채팅이 다시 열린다 → 새로고침 뒤에 같은 프로젝트를 본다. 라이트와 다크에서 콘솔 오류·경고 0건이다. 기본 작업공간 토스트가 뜨지 않는다. 두 장치와 메뉴 가림은 일부러 망가뜨려 시험이 실패하는 것을 봤다. 화면용 API가 거절하면 실패 알림이 뜨고 화면이 그대로 남는 것도 조합 시험이 본다. 자식 슬롯은 화면 둘을 임시로 등록해 띄워 봤다. 단위 시험은 98개다(저장소, 내비게이션 규칙, API 클라이언트, 동작, 구독, 화면 자리).
  - 같이 고친 것: `@cs/api/wire`를 브라우저 프로그램이 타입 검사할 수 있게 했다(프로젝트 계층의 타입 전용 진입점만 가져오고, 연산 선언의 타입은 `wire-operation.ts`로 떼었다).
  - 1-3에서 확인했다: 메시지가 오가는 것, 대화가 있는 세션이 여럿일 때의 목록과 전환.
  - 후속: 홈에서 우측 패널을 아예 숨길지(지금은 접기만 한다. 숨기려면 dsh 내부에 기대는 장치가 하나 더 든다. 사용자가 정한다), 브라우저 탭 제목과 파비콘(dsh 내부에 기대는 장치가 필요하다. 하기로 하면 정한다), URL에 위치를 적어 뒤로 가기를 지원하는 것, 세션의 이름 바꾸기와 보관, 화면용 API 클라이언트를 `@cs/ui-kit`으로 옮기는 것(3-2), 실행 취소 단축키(3-2 이후), 연산 선언의 타입을 브라우저에서 쓰는 법(3-3), 마크와 모양 다듬기(3-1).
