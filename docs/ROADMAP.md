**채팅에서 워크플로 하나를 local ComfyUI로 실행하고, 결과 이미지가 가운데 갤러리에 뜬다.**

- 단계 하나가 브랜치 하나·PR 하나다(`AGENTS.md` "브랜치·커밋·병합").

- 끝낸 단계는 아래에서 `[x]`로 바꾸고 무엇을 어느 패키지에서 했는지 한 줄로 적는다. 남긴 일은 `[ ]`나 "후속"으로 적는다.

- 단계가 정해야 하는 "미정"(`docs/DECISIONS.md`)은 단계 계획 문서에 안을 쓰고 사용자가 확인한 뒤에 구현한다.

  - 1-3에서 확인했다: 메시지가 오가는 것, 대화가 있는 세션이 여럿일 때의 목록과 전환.
  - 후속: 홈에서 우측 패널을 아예 숨길지(지금은 접기만 한다. 숨기려면 dsh 내부에 기대는 장치가 하나 더 든다. 사용자가 정한다), 브라우저 탭 제목과 파비콘(dsh 내부에 기대는 장치가 필요하다. 하기로 하면 정한다), URL에 위치를 적어 뒤로 가기를 지원하는 것, 세션의 이름 바꾸기와 보관, 화면용 API 클라이언트를 `@cs/ui-kit`으로 옮기는 것(3-2), 실행 취소 단축키(3-2 이후), 연산 선언의 타입을 브라우저에서 쓰는 법(3-3), 마크와 모양 다듬기(3-1).
- [ ] **3-1 자체 부품** — dsh 기본 부품에 없는 것(표, 슬라이더, 셀렉트, 트리, 카드 등)을 만든다. 토큰·부품·사용 예를 이 저장소의 `docs/DESIGN.md`에 쓴다. 기존 앱의 `src/components/ui`(942줄)와 기존 저장소의 `comfy-studio/docs/DESIGN.md`가 참고다.
- [ ] **3-2 첫 화면: 갤러리** — 화면용 API에서 에셋을 읽어 그리고, 이벤트가 오면 다시 읽는다.
- [ ] **3-3 워크플로·생성·배치 검토** — 워크플로 목록, 실행 폼, 진행률, 배치 검토.
- [ ] **3-4 채팅 안의 카드** — 도구 결과와 제안(생성 제안, 그래프 패치 제안, 삭제 제안 등)을 카드로 그리고 승인·거절을 받는다. 조합 시험은 가짜 LLM 서버로 턴을 돌려서 본다(`docs/DSH.md` "모델이 있어야 하는 시험").
- [ ] **3-5 설정 화면** — ComfyUI 서버 등록·연결 테스트·모델 목록을 dsh 설정 화면의 슬롯에 넣는다.
- [ ] **3-6 그 밖의 화면** — 캐릭터, 프리셋, 히스토리(기록) 탭 등. 범위는 1-4가 정한다.

## 계획 4 — Comfy 연결

ComfyUI 서버와 말하는 부분이다. 기존 `comfy-studio`의 `src/lib/comfy`를 옮기는 데서 출발한다. 읽을 문서는 `docs/LEGACY.md` "ComfyUI 연동"이다.

- [x] **4-0 연동 라이브러리 이식** — 기존 `src/lib/comfy`에서 `runner.ts`와 `input-image.ts`를 뺀 21개 파일과 그 테스트 18개, 보조 모듈 다섯(`png-text`, `png-text.server`, `match`, `sigv4`, `keys`)과 그 테스트 셋을 `packages/comfy`(`@cs/comfy`)로 옮겼다(2026-11-28). dsh에 의존하지 않고 번들의 행이 없다. 옮긴 테스트 253개가 통과한다. 공개 범위는 사용자가 정했다(전부 공개. 특정 배포를 가리키는 이름은 일반 이름으로 바꿨다. `docs/DECISIONS.md` "확정"). 새 자리와 원본과 달라진 곳은 `docs/archive/PLAN_4-0.md`.
  - 후속: 주석 몇 곳이 기존 앱의 모듈을 가리킨다. 그 자리를 대신할 모듈이 생기는 4-1·4-2에서 고친다. `events.ts`의 진행 이벤트 모양과 내보낼 모듈의 범위는 4-2에서 다시 본다.
- [ ] **4-1 서버 등록과 자격 증명** — ComfyUI 서버 목록을 어디에 둘지 정하고, 키는 dsh 자격 증명 저장소에 둔다. 연결 테스트.
  - 완료 기준: 키가 설정 파일·기록·브라우저 응답에 평문으로 남지 않는다.

  - 완료 기준: 가짜 ComfyUI 서버를 상대로 한 시험과 실제 local ComfyUI 한 번.
